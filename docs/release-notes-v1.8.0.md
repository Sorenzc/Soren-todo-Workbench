# v1.8.0 · 维护面板、归档搜索与几处顺手

## 这一版：把「用得久了才会出问题」的地方补上

前几版一直在加功能，这一版换个方向：处理那些平时不吭声、出事才发现的问题——库和归档对不上、找不到半年前做完的那件事、逾期攒了一堆只能一条条改。

### 体检与清理

设置里新增「体检与清理」。它只读地检查一遍，然后把结果摊开给你看：

- 数据库多大、WAL 多大、`PRAGMA quick_check` 是否通过；
- 归档目录有几个文件、占多少空间；
- 未完成 / 已完成 / 已删 / 速记 各多少条；
- 有多少「失效关联」（文件夹被移走或删掉后，关联会标成丢失）；
- 服务进程还活着没有（pidfile 过期时也能看出来）；
- 有几份备份、最近一份是什么时候。

发现两类不一致时会多出两节：

- **孤儿归档**：库里已经没有这条任务了，但 `archive/` 里还留着它的 md。可以一键删掉（会先问你）。
- **缺失归档**：任务还在、但标记的归档文件不在了。可以点「重新生成归档」补齐。

只读检查、手动清理，不会自己动你的文件。

### 归档全文搜索

归档本来就是普通 Markdown，所以这一版直接在文件里搜，没有额外的索引：

- 归档视图顶部多了搜索框，输入停 300ms 就开始扫；
- 命中的结果给标题、日期、上下文片段，点一下在资源管理器里定位到那篇文件；
- 月度索引里也写着标题，会跟真正的归档重复——有任务归档命中时就不再返回索引。

半年前那句「消防年检回执归档在哪个月」，现在一句话就能翻出来。

### 逾期批量改期

「今天」视图的逾期组，原来只有「一键完成」，现在多了「全推到明天」：

- 一次改一批，走 `POST /api/tasks/bulk-reschedule`，单条失败不中断；
- 改期只动日期，不改完成状态；已完成 / 已放弃的会被跳过；
- 结尾统一汇报「已挪到 2026-11-12：6 条」。

### 例行跳过一期

每天 / 每周的例行待办，右侧多了「跳过这一期」：

- 这一期不做，系列照常往后滚，**不会留下一条「已完成」的假记录**；
- 每月例行不支持这样跳（它是一期一期排好的），要跳过直接改那一期的日期；
- 跳过的日期和下一期会写在提示里。

### 提醒稍后再说

到点提醒的 toast 上多了「稍后 10 分钟」「稍后 1 小时」：

- 走 `POST /api/tasks/:id/snooze`，把 `remind_at` 往后推并重新武装 `remind_fired`；
- 页面开着、托盘通知都走同一个刷新口径，不会重复弹。

## 怎么升级

覆盖安装即可，数据库从 v7 起不再需要迁移；老库第一次启动会自动建表。数据都在 `data/` 和 `archive/` 里，升级前建议先点一次「立即备份」。

## 已知限制

- 归档搜索是顺序扫文件，归档上万篇时会慢一点（目前按 40 条上限截断）；
- 每月例行不支持「跳过这一期」，请直接改日期或取消系列；
- 体检里的「清理孤儿」只删 `archive/` 里没人引用的 md，不碰月度索引。
