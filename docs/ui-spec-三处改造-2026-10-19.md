## 2. 全局字号系统（改造 3）

### 2.1 字阶：9 档（token 用 rem，1rem = 16px，容器尺寸继续用 px）

```css
:root {
  /* ── 字号（rem：跟随浏览器/系统字号设置，px 值写在注释里便于对稿）── */
  --fs-micro: .6875rem;  /* 11 角标、日期、字段小标签、键帽 */
  --fs-xs:    .75rem;    /* 12 辅助说明、计数、星期、状态栏 */
  --fs-sm:    .8125rem;  /* 13 元信息、按钮、输入框、提示 */
  --fs-md:    .875rem;   /* 14 正文：导航、分类、月历标题、笔记 */
  --fs-lg:    .9375rem;  /* 15 列表标题、品牌、例行标题 */
  --fs-xl:    1rem;      /* 16 详情标题、弹窗标题 */
  --fs-2xl:   1.125rem;  /* 18 新建待办大标题 */
  --fs-3xl:   1.375rem;  /* 22 视图标题 h1 */
  --fs-4xl:   1.625rem;  /* 26 统计数字 */

  /* ── 行高 ── */
  --lh-tight: 1.3;  /* 大标题、统计数字 */
  --lh-ui:    1.4;  /* 单行控件、列表项 */
  --lh-meta:  1.45; /* 元信息、副标题 */
  --lh-body:  1.6;  /* 正文段落、提示、空状态 */
  --lh-read:  1.7;  /* 笔记、长文阅读区 */
}
```

**为什么 rem 而不是 px**：字号是唯一需要跟随系统/浏览器「字体大小」设置的东西。用 rem 后，Windows 显示设置里放大字号（不缩放整个界面）时文字会跟着变大；容器用 px + 现有 `min-height`（不是 `height`）+ 已经存在的 `text-overflow: ellipsis`，实测不会撑破。若你更想要「绝对像素可控」，把上面的 rem 换回注释里的 px 值即可，其余规则不用动。

### 2.3 行高与行距规则（关键）

字号 +1px 时如果行高比例不动，行盒会长 1.5px 并连锁推高所有卡片；本方案用**降比例、保行盒**的办法：

| 场景 | 现值 | 新值 | 行盒变化 |
|---|---|---|---|
| 列表标题 `.row-title` | 14×1.5 = 21 | 15×1.4 = **21** | 0（行高 36→38 纯粹是留白） |
| 元信息 `.row-cat` | 12×1.5 = 18 | 13×1.45 = 18.85 | +0.85 |
| 辅助 `.statusbar` | 11.5×1.5 ≈ 17 | 12×1.5 = 18 | +1 |
| 正文段落 `.notes` | 12.5×1.65 ≈ 20.6 | 14×1.7 = 23.8 | +3.2（阅读区，值得） |
| 大标题 `h1` | 20×1.5 = 30 | 22×1.3 = 28.6 | −1.4（更稳） |

**三条硬规则**：①单行控件/列表项一律 `--lh-ui`（1.4），不要把 1.5 用到列表上；②任何多行文本区（笔记、提示、空状态）用 `--lh-body`/`--lh-read`，行距 ≥ 1.6；③全表**不再出现 1.4 以外的奇怪比值**（现在散落 1.45/1.5/1.65/1.9 四套）。

### 2.5 卡片与详情面板要不要跟着调

- **卡片**：宽度、圆角（10）、1px 描边、阴影都不动；只把 `--row-h` / `--row-sep-inset` / `--card-gap` 按上表改。列表列宽 `2px 16px 1fr 84px 26px 64px 16px` **一格都不用改**：实测 13px 下 `.row-cat`（5 字 = 65px + 圆点 7px）在 84px 内不裁剪，`.row-due`（「逾期 9 天」= 56px）在 64px 内不裁剪。
- **详情面板**：**宽度 380px 不变**。实测内容宽 347px，14px 笔记每行约 24.8 个汉字，正落在 24–28 字的舒适区；加宽到 400px 每行 26.2 字收益极小，却会从列表里抢走 20px（列表 760→740）。只改内部字号（见 2.2 详情表）+ `.notes` 行高 1.7；`.field` 两列网格、`.prio-pills`、`.tm-*` 控件尺寸不动。
- 实测 380px 下详情面板**零裁剪**（`scrollWidth > clientWidth` 的元素为 0），见 `docs/design-preview/8-详情面板-1440.png`。

### 2.6 窄屏回退

| 断点 | 策略 | 实测 |
|---|---|---|
| ≥1120 | 全套放大（默认） | 顶栏 actions 370，搜索 460，无溢出 |
| 900–1120 | 字号**不降**，`.icon-btn` 回到 `padding 0 6px` | 876 视口下 actions 326 / 搜索 229，无溢出 |

## 4. 日历「上个月 / 下个月」（改造 2）

### 4.1 问题定性

不是「按钮太小」一个毛病，是**三个**：①22×22 / 24×24 太小；②`‹ ›` 用的是字符，放大后基线漂移、笔画变细；③箭头被 `flex:1` 的标题推到浮层两端（165px / 184px 之外），视觉上和标题不是一个整体。所以修法必须是「**标题 + 两个箭头 = 一个居中的簇**，✕ 单独靠右」。

### 4.2 目标结构（三处共用同一套类名）

```html
<div class="cal-head">                <!-- .tm-cal-head 同理 -->
  <div class="cal-title-group">
    <button class="cal-nav" type="button" aria-label="上个月" title="上个月（PgUp）">
      <svg viewBox="0 0 16 16" width="14" height="14" aria-hidden="true"><path d="M9.6 3.4 5.4 8l4.2 4.6"/></svg>
    </button>
    <span class="cal-ym">2026 年 10 月</span>
    <button class="cal-nav" type="button" aria-label="下个月" title="下个月（PgDn）">
      <svg viewBox="0 0 16 16" width="14" height="14" aria-hidden="true"><path d="M6.4 3.4 10.6 8l-4.2 4.6"/></svg>
    </button>
  </div>
  <button class="cal-x" type="button" aria-label="关闭">✕</button>
</div>
```

> 现状差异：顶栏 `renderCalendar()`（`app.js:919-924`）的三个按钮**都没有类名**（只有 `title`），必须补 `class: 'cal-nav'` / `class: 'cal-x'`；内嵌 `drawCal()`（`app.js:1521-1525`）的两个箭头**已经有** `.cal-nav`，只差包一层 `.cal-title-group` 和把字符换成 SVG。
> `el()` 是 `document.createElement` 包出来的，**不能直接建 SVG 命名空间节点**，所以 SVG 用一行 `innerHTML` 挂进去：

```js
// app.js —— 三处日历共用
function calNav(dir, onClick) {
  const path = dir === 'l' ? 'M9.6 3.4 5.4 8l4.2 4.6' : 'M6.4 3.4 10.6 8l-4.2 4.6';
  const b = el('button', {
    class: 'cal-nav', type: 'button',
    'aria-label': dir === 'l' ? '上个月' : '下个月',
    title: dir === 'l' ? '上个月（PgUp）' : '下个月（PgDn）',
    onclick: onClick,
  });
  b.innerHTML = `<svg viewBox="0 0 16 16" width="14" height="14" aria-hidden="true"><path d="${path}" fill="none" stroke="currentColor" stroke-width="1.7" stroke-linecap="round" stroke-linejoin="round"/></svg>`;
  return b;
}
```

若不想动 SVG，退一步也能接受：保留 `‹`/`›` 字符，把 `.cal-nav` 的 `font-size` 设成 **18px / line-height 1 / padding-bottom 2px**——但 18px 的 `‹` 笔画会偏细、上下位置随字体浮动，跨系统不一致，所以仍推荐 SVG。


- `.cal-ym` 不再 `flex:1`，改为 `flex:none; min-width:96px; text-align:center` —— 保证「9 月」和「10 月」翻页时箭头**不跳动**；
- `‹ ›` 换成 14×14 SVG 折角（`stroke-width 1.7`、`stroke-linecap round`），放大后仍锐利；
- 标题仍居中：`✕` 用绝对定位，避免它把整簇推偏。
- **不要**把标题改成左对齐（会与居中的 7 列网格脱节），也不要继续把字符 `‹` 调到 16–18px（形变）。

### 4.3 尺寸 token 与实测结果


|---|---|---|---|
