# 待办工作台 1.9.5

## 这一版：把「发布」这件事也自动化了

前两版连着在安装包上翻车（路径校验把所有绝对路径判成非法、按钮被滚动藏起来），说明靠人眼盯着截图不够。这版没加新功能，只把两条最容易出错的流程做成了脚本。

### 1. `scripts/verify-setup.mjs`：安装包自动验收

打包之后自动跑一遍，十项检查，任何一项不过就退出非 0：

- 向导第 1/2/3 页：能出图、退出码为 0（内部会自检按钮是否可见、文字是否越界）
- 静默安装到临时目录，退出码为 0
- 程序文件落在 `app\<版本>\`，`node.exe` 与 `src/server.mjs` 都在
- `config.json` 里的版本号与 `dataDir` 和安装时给的一致
- 注册表卸载项的 `DisplayVersion` 是当前版本
- 启动器 `--selftest` 能跑通（本机已有服务在跑时只提示，不算失败）
- 静默卸载后程序目录消失、注册表项被移除

跑完会自动删临时目录和注册表，不留垃圾。加 `--keep` 可以保留现场检查。

### 2. `scripts/release.mjs`：一条命令发布

原来发布要手工敲十来个命令，容易漏掉「清演示数据」或「校验资产」。现在一条：

```bash
node scripts/release.mjs --notes docs/release-notes-v1.9.5.md
```

它会依次做：清演示数据（停服务、清空任务/速记/系列、删备份与截图、清归档，并用 SQLite 断言三张表都是 0）→ 提交 → 推送（`github.com` 连不上时自动改走 Git Data API 逐提交重放）→ 打 tag → 打包 → 安装包验收 → 上传固定名资产 → 读回 release 校验资产状态。

常用开关：`--dry-run`（只检查前置条件）、`--no-build`（用 dist 里已有的包）、`--skip-verify`（不建议）、`--title`/`--message`。

## 怎么升级

1. 设置 → 版本与更新 → 检查更新
2. 下载安装包，等进度到 100% 并显示「sha256 校验通过」
3. 从托盘退出工作台，运行下载好的安装包覆盖安装

数据和归档都在独立目录，升级不覆盖。

## 已知限制

- 自动验收只覆盖安装/卸载与向导排版，不覆盖「装完双击图标是否真的能开浏览器」这一步（那一步靠 `--selftest` 间接验证）
- `release.mjs` 假设仓库是单 main 分支、Tag 用 `v<版本号>`；换仓库结构要改脚本里的 `repoSlug()` 与 tag 规则
